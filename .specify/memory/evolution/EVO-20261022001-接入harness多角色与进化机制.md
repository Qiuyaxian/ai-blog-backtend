# 进化记录 - 2026-10-22 01:40

## 1. 任务/问题场景

参考 `harness-sdd` 模板，给本仓库（NestJS 9 + MongoDB/Mongoose + Redis 纯后端）
接入 Harness 多 Agent 能力：多角色规则、AGENTS.md 集成、进化记录机制。

接入过程中发现模板不能照搬：

1. 模板按 Next.js 全栈项目编写，含 frontend-agent、TypeORM/PostgreSQL、裸 SQL 禁令，
   与本仓库 Mongoose + MongoDB 事实冲突。
2. 模板 AGENTS.md 允许 `/speckit.implement` 直接实现，与本仓库宪法/AGENTS.md §7
   「禁止调用 `/speckit.implement`、执行权归 Superpowers、handoff 状态机」冲突。
3. 模板把规则分散在根 AGENTS.md、`.cursorrules`、`specs/coding.md`，本仓库已有
   docs/ 文档体系、context.md 动态记忆和 `.cursor/rules/*.mdc`，照搬会制造重复事实源。

## 2. 根因分析

- 参考模板是通用脚手架，角色规则与具体技术栈、既有治理流程耦合度低，直接复制会在
  本仓库产生相互矛盾的硬约束（Mongoose vs TypeORM、implement 命令、分层命名）。
- 项目缺少「角色视角」的职责边界文件（现有规则按主题组织：宪法、coding-style、
  工作流），多 Agent 协作时角色不知道自己该在哪个环节介入、哪些动作禁止。
- 项目缺少跨任务的经验闭环：context.md 记录会话事实，但没有把重复教训强制归并到
  规范的机制，同类问题可能在后续 feature 中再现。

## 3. 最终解决方案

1. 按本仓库技术栈重写四个角色规则（arch/dev/test/devops），不设前端角色：
   - 数据层全部改为 Mongoose 事实（`@InjectModel`、E11000 转业务码、`_id` 游标、
     生产 `autoIndex:false`、非法 ObjectId → 400）。
   - 缓存只认现有 `CacheService`（正整数 TTL、未命中 null、client 不导出）。
   - 测试对齐现状：Jest 同目录 `*.spec.ts`、E2E 自举 + supertest + `--runInBand`、
     测试库 `ai_blog_test`、`x-test-user` 桩的存在与删除条件。
2. 角色规则全部声明为宪法与 AGENTS.md §7 的下位文件：规划权/执行权分离、TDD、
   handoff 状态机对所有角色生效；明确禁止 `/speckit.implement`。
3. 新增 `workflows/development-workflow.md` 把 11 阶段流水线映射到本仓库
   §7 三阶段 + 四角色交接物，不另起流程；新增 `commands.md` 只收录真实存在的
   Spec-Kit 技能命令与 `/role`、`/evolve` 两个角色层指令。
4. 建立进化闭环：`.specify/memory/evolution-mechanism.md` + 模板 + 编号记录 +
   索引；规则归并到既有唯一权威文件（docs/ 文档与 ADR），不新建重复规范。
5. `.cursor/rules/harness-agents.mdc` 按文件类型给角色路由建议（建议而非自动切换），
   兼容现有 always-on 规则。
6. 根 AGENTS.md 以「新增 §7A」方式集成，不改写既有 §1–§9 编号与内容。
