# 功能规格说明：Swagger 接口文档接入（API Documentation）

**功能分支**：`004-swagger-docs`

**创建日期**：2026-10-24

**状态**：Draft

**输入**：用户描述："新需求，新增 swagger 说明文档接入，使用 @nestjs/swagger ^7.4.2"

## 澄清记录

### 会话 2026-10-24

- Q: 本期文档覆盖范围？ → A: 接入文档 UI，并给现有 user/auth 全部业务接口、请求 DTO、响应结构补齐文档注解（含成功与主要错误响应）；不做在线 Mock、不导出离线 SDK。
- Q: 哪些环境开放文档页面？ → A: local 与 uat 开放；production 关闭，生产环境请求文档路径返回 404，不暴露任何接口结构。
- Q: 是否支持在文档页内带令牌调试？ → A: 是。文档页提供 Bearer 鉴权入口，填入现有不透明访问令牌后可直接调用受保护接口；登出等本人接口、管理员接口的鉴权要求与真实接口一致。
- Q: 文档访问路径？ → A: `/api-docs`（页面）；配套的机器可读文档源文件与页面同源、仅在允许环境暴露。
- Q: 文档组件版本？ → A: 需求指定 @nestjs/swagger ^7.4.2；已核实其 peerDependencies 同时支持 NestJS 9 与 10，与当前 NestJS 9 技术栈兼容，无需升级框架；Fastify 相关可选依赖不需要（本项目使用 Express）。

## 用户场景与测试 _(强制)_

### 用户故事 1 - 在浏览器查看完整在线接口文档（优先级：P1）

后端开发者或前端/测试协作者在 local、uat 环境打开一个固定页面，即可看到本服务全部业务接口的在线说明：按模块分组的接口清单、HTTP 方法与路径、请求参数/请求体字段（含类型、是否必填、取值约束、示例）、成功响应字段与类型、主要失败响应的错误形态。文档内容与实际接口契约一致，无需阅读后端源码。

**为何此优先级**：可访问、内容完整的文档页面是本功能的最小可用闭环；没有它，其余能力无从谈起。

**独立测试**：在 local 启动服务后访问文档页面，能看到 auth 与 users 两个模块共 9 个业务接口；逐一核对登录、注册两个公开接口的入参约束（必填、长度、邮箱格式等）与成功响应字段与真实接口一致。

**验收场景**：

1. **假设** 服务运行在 local 环境，**当** 协作者访问 `/api-docs`，**那么** 页面正常打开，显示服务名称、版本与按模块分组的接口清单。
2. **假设** 文档页面已打开，**当** 查看任一业务接口，**那么** 该接口展示 HTTP 方法、完整路径、功能说明、请求参数/请求体每个字段的类型、是否必填、校验约束与含义，以及成功响应的状态码与字段结构。
3. **假设** 文档页面已打开，**当** 查看登录接口，**那么** 其请求体包含「登录标识」与「密码」两个必填字段并标注长度约束；成功响应展示访问令牌、到期时间与用户公开资料字段，且不出现密码字段。
4. **假设** 文档页面已打开，**当** 查看注册接口，**那么** 密码字段标注「8–64 位且须同时含字母与数字」等真实校验规则；用户响应模型固定只含 6 个公开字段，不出现密码、软删除标记、内部存储字段。
5. **假设** 文档页面已打开，**当** 查看任一接口，**那么** 文档至少标注该接口在「参数校验失败」「未认证」「权限不足」「资源不存在」「业务冲突」中实际会发生的失败响应及其统一错误体形态。
6. **假设** 文档页面已打开，**当** 查看管理员接口，**那么** 文档明确标注其需要管理员权限；查看本人接口标注需要登录；公开接口（登录、注册）不标注鉴权要求。

---

### 用户故事 2 - 在文档页内带令牌直接调试接口（优先级：P2）

协作者先调用登录接口获得访问令牌，在文档页的鉴权入口填入令牌后，可直接在页面上调用受保护接口与管理员接口，请求自动携带 `Authorization: Bearer <token>`，无需自行构造请求头或切换到其他工具。

**为何此优先级**：在线调试是 Swagger 工作流的核心价值之一，降低联调成本；但它依赖文档内容本身先完整，故列 P2。

**独立测试**：在文档页登录接口直接发起一次成功登录，复制令牌并填入鉴权入口，随后调用「查看本人资料」成功返回；不填令牌调用同一接口得到未认证响应。

**验收场景**：

1. **假设** 协作者通过登录接口获得有效访问令牌，**当** 其在文档页鉴权入口填入该令牌后调用「查看本人资料」，**那么** 请求成功并返回该令牌对应用户的公开资料。
2. **假设** 未填入任何令牌，**当** 协作者在文档页调用受保护接口，**那么** 得到与真实接口一致的未认证错误响应。
3. **假设** 协作者填入普通用户令牌，**当** 其调用管理员接口，**那么** 得到权限不足错误；填入管理员令牌后调用成功。
4. **假设** 协作者填入已登出（已吊销）或伪造的令牌，**当** 调用受保护接口，**那么** 得到未认证错误，行为与接口真实鉴权完全一致。
5. **假设** 协作者在鉴权入口填入令牌后调用登出接口，**那么** 登出成功；此后页面保持该令牌再次调用受保护接口返回未认证（即时吊销在文档调试链路同样成立）。

---

### 用户故事 3 - 生产环境不暴露接口文档（优先级：P1）

运维与服务所有者在 production 环境运行同一套服务时，文档页面及其机器可读源文件均不可访问：访问文档路径得到与访问任意未知路径相同的结果（404），外部人员无法借文档枚举接口结构。该开关随环境配置生效，不依赖人工在发布时修改代码。

**为何此优先级**：安全合规是宪法原则 IV 的默认要求；即使功能最小化上线，也绝不能在生产意外暴露完整接口目录，故与 P1 同级的硬约束。

**独立测试**：以生产环境配置启动服务，访问 `/api-docs` 及其机器可读文档源路径均返回 404；同时登录、注册、健康检查等既有接口行为不受影响。

**验收场景**：

1. **假设** 服务以 production 配置运行，**当** 外部访问者请求 `/api-docs`，**那么** 返回 404 且不返回任何文档内容。
2. **假设** 服务以 production 配置运行，**当** 访问者请求文档页面引用的机器可读文档源路径，**那么** 同样返回 404。
3. **假设** 服务以 local 或 uat 配置运行，**当** 访问 `/api-docs`，**那么** 文档正常可访问；即环境差异由配置自动决定。
4. **假设** 生产环境关闭了文档，**当** 既有业务接口（登录、注册、受保护接口、健康检查）被正常调用，**那么** 其行为与本功能上线前完全一致，文档接入不改变任何运行时业务行为。

---

### 边界场景

- 文档注解与真实契约漂移：后续接口/DTO 变更时，文档内容必须能随代码评审被核对；本期通过「注解与 DTO 校验同源、评审清单包含文档核对」控制，不引入独立的契约测试框架。
- 文档接入本身不得改变任何接口的运行时行为（状态码、响应字段、校验规则、鉴权判定）；文档组件只读取元数据，不参与请求处理。
- 生产关闭文档时，不能只是页面空白或静态资源仍可下载：文档 UI 与机器可读源都必须不可访问。
- 文档中任何位置（请求示例、响应模型、字段说明）都不得出现真实密码、真实令牌、连接串或密钥；示例值使用占位数据。
- 非法/过期/已登出令牌在文档调试链路中的结果必须与外部调用完全一致，不提供任何调试旁路。
- 健康检查与根路径等基础设施接口是否纳入展示：本期可在文档中可见但不要求逐字段细注；业务接口（auth、users）必须 100% 完整标注。
- 文档组件版本与 NestJS 主版本的兼容性已在澄清中核实；计划阶段须锁定不引入额外运行时依赖，文档组件在生产环境不产生文档构建开销以外的额外负担。
- 文档组件可能抛出的自身异常不得影响正常业务接口（文档相关路由与业务路由隔离）。

## 需求 _(强制)_

### 功能需求

- **FR-001**：系统 MUST 在 local 与 uat 环境提供一个可通过浏览器访问的在线接口文档页面，固定路径为 `/api-docs`。
- **FR-002**：系统 MUST 在与文档页面同源的路径提供机器可读的接口描述源，供文档页面加载；该源在 production 环境 MUST 与文档页面同样不可访问（404）。
- **FR-003**：系统 MUST 按业务域对接口分组展示，至少包含「认证（auth）」与「用户（users）」两个分组；每个接口 MUST 展示 HTTP 方法、路径与中文功能说明。
- **FR-004**：文档 MUST 覆盖现有全部 9 个业务接口：登录、登出、注册、查看本人资料、修改本人邮箱、管理员用户列表、管理员查看用户详情、管理员设置/取消管理员、管理员软删除用户。
- **FR-005**：每个请求体/查询参数 DTO 的字段 MUST 在文档中标注：字段名与含义、数据类型、是否必填、以及与实际校验一致的约束（长度上下限、邮箱格式、字母数字组合、MongoDB ID 格式、分页缺省值与上限等）；文档约束 MUST NOT 与真实校验规则矛盾。
- **FR-006**：文档 MUST 展示每个接口成功响应的状态码与响应体结构；用户相关响应 MUST 只包含既有公开字段（id、username、email、isAdmin、createdAt、updatedAt），MUST NOT 出现密码或其他内部存储字段。
- **FR-007**：文档 MUST 标注每个接口实际可能返回的主要错误响应（至少覆盖会发生的：参数校验错误 400、未认证 401、权限不足 403、资源不存在 404、业务冲突 409 等），错误响应模型 MUST 与既有统一错误体（code/message/statusCode）一致。
- **FR-008**：文档 MUST 标明每个接口的鉴权要求：公开（登录、注册）、需登录（本人接口）、需管理员（管理员接口）；鉴权标注 MUST 与真实守卫配置一致。
- **FR-009**：文档页面 MUST 提供 Bearer 鉴权入口；填入令牌后页面内发起的请求 MUST 以 `Authorization: Bearer <token>` 请求头出示，且这是唯一的调试令牌出示方式（MUST NOT 提供 URL 参数等旁路）。
- **FR-010**：经文档页面发起的调用 MUST 走与外部调用完全相同的请求管线（校验、鉴权、异常归一），MUST NOT 存在仅文档可用的测试旁路；伪造、过期、已登出令牌 MUST 被真实拒绝。
- **FR-011**：系统 MUST 仅在非 production 环境启用文档（local、uat 开放）；production 环境下文档页面、机器可读源及其静态资源 MUST 全部不可访问，访问文档路径返回 404；该行为 MUST 由环境配置驱动，不依赖发布时人工改码。
- **FR-012**：接入文档能力 MUST NOT 改变任何既有接口的运行时行为（响应、状态码、校验、鉴权、日志均不变）；文档组件 MUST NOT 参与业务请求处理。
- **FR-013**：文档内容与示例 MUST NOT 包含真实密码、真实访问令牌、数据库连接串或任何密钥；示例一律使用明显的占位值。
- **FR-014**：本期 MUST NOT 引入离线代码生成、SDK 生成、契约测试框架、Postman 导出之外的额外平台；仅引入需求指定的文档组件一个直接依赖，且该依赖 MUST 与现有 NestJS 主版本兼容（已核实支持 NestJS 9），MUST NOT 为此升级 NestJS 或引入 Fastify 相关可选依赖。
- **FR-015**：文档能力 MUST 可通过现有自动化测试验证其关键承诺：开放环境可访问性、生产关闭（404）、文档源包含全部业务接口路径与鉴权定义；既有单测与端到端测试 MUST 保持全部通过。
- **FR-016**：健康检查与根路径接口 MAY 在文档中作为基础设施分组可见，但不要求逐字段细注；本期 MUST NOT 为文档目的修改任何业务接口的路径或响应结构。

### 关键实体 _(涉及数据时包含)_

本功能不引入业务数据持久化，文档元数据为随代码构建的描述性信息：

- **接口描述（API Operation，描述性元数据）**：一个 HTTP 接口的文档单元。关键属性：所属分组、方法与路径、功能说明、鉴权要求（公开/登录/管理员）、请求模型引用、成功响应模型、错误响应集合。
- **请求/响应模型（Schema，描述性元数据）**：字段名、类型、是否必填、约束说明、示例；请求模型与现有 DTO 一一对应，响应模型复用现有公开视图（如用户公开资料 6 字段、登录结果、登出结果、分页列表）。
- **环境开关（Environment Flag，配置项）**：决定文档是否启用的环境配置，仅 local/uat 启用、production 关闭。

## 成功标准 _(强制)_

### 可衡量结果

- **SC-001**：在 local 环境，协作者从打开文档页到成功调通「登录 → 带令牌查看本人资料」全程不依赖后端人员口头说明或阅读源码，100% 可在文档页内独立完成。
- **SC-002**：现有 9 个业务接口在文档中的覆盖率为 100%，且每个接口的请求字段必填性/约束与代码校验规则核对一致（评审抽样核对 0 处矛盾）。
- **SC-003**：文档中用户响应模型出现敏感字段（密码、内部字段）的次数为 0；示例中真实密钥/真实令牌出现次数为 0。
- **SC-004**：production 配置下访问文档页与机器可读源路径 100% 返回 404；local/uat 下 100% 可访问。
- **SC-005**：在文档页内以「无令牌 / 普通用户令牌 / 管理员令牌 / 已登出令牌」四种身份调用受保护与管理员接口，返回结果与接口真实行为 100% 一致（未认证、成功、权限不足、未认证）。
- **SC-006**：接入后既有自动化测试（单元 + 端到端）通过率 100%，无业务接口行为回归；`pnpm lint && pnpm test` 退出码 0。
- **SC-007**：新增文档相关自动化用例 100% 覆盖三条关键承诺：开放环境页面可访问、生产环境 404、文档源包含全部 9 个业务接口路径。
- **SC-008**：引入的直接生产依赖数量为 1（需求指定的文档组件），NestJS 主版本升级数为 0。

## 假设

- 文档组件采用需求指定的 @nestjs/swagger ^7.4.2；已核实其 peerDependencies 为 `@nestjs/common/core ^9 || ^10`，与本项目 NestJS 9 兼容；技术取舍与 ADR 在 plan 阶段记录。
- 本项目使用 Express 平台适配器，无需 Fastify 相关可选依赖（澄清记录）。
- 文档仅服务于内部协作（开发、前端、测试），uat 环境访问控制由既有网络/部署边界承担；本期不为文档页本身加登录墙（页面可打开，但接口调试仍受真实鉴权约束）。
- 文档元数据以代码注解方式与 DTO/Controller 同源维护，不维护独立的手写接口文档文件，以减少漂移；接口变更评审需核对文档注解（纳入评审清单）。
- 环境判定沿用现有按 `NODE_ENV` 自动加载环境配置的机制，新增一个文档开关配置，默认 local/uat 开、production 关。
- 业务接口现状以 001 用户模块、003 登录鉴权已交付的 9 个接口为准；健康检查、根路径为基础设施接口，可粗粒度可见。
- 统一错误体（code/message/statusCode）、统一响应字段与鉴权机制均沿用既有实现，本功能只描述、不修改。
- 文档功能不涉及数据库变更、不涉及缓存、不新增业务字段，无 expand-contract 需求。
- SC-001 的可用性由功能演示与手工冒烟验证；不引入外部文档平台或可用性度量系统。
