# Backup — 备份与恢复

本文档说明本服务的数据备份策略、备份方式、恢复流程与演练要求。

## 1. 备份范围

| 数据         | 备份方式                                     | 频率                      | 保留       |
| ------------ | -------------------------------------------- | ------------------------- | ---------- |
| MongoDB 数据 | 快照（生产）/ mongodump（开发） + oplog 归档 | 每日快照 + oplog 持续归档 | 30 天      |
| Redis 数据   | RDB / AOF                                    | 按策略                    | 7 天       |
| 配置文件     | Git / 配置中心                               | 变更即备份                | 长期       |
| 环境变量     | 加密存储                                     | 变更即备份                | 长期       |
| 日志归档     | 对象存储                                     | 每日                      | 按合规要求 |

## 2. 备份策略

### 2.1 MongoDB 备份

| 项目     | 说明                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| 全量备份 | 生产用文件系统/云盘**一致性快照**（带 oplog）；开发/小库可用 `mongodump`        |
| 增量备份 | 生产持续归档 oplog，支撑时间点恢复（PITR）；oplog 保留窗口须大于全量周期        |
| PITR     | 快照恢复后重放归档 oplog 到目标时间点；仅靠每日 dump+oplog 流程脆弱，不用于生产 |
| 备份位置 | 对象存储 / 异地机房                                                             |
| 加密     | 备份文件加密存储                                                                |
| 校验     | 备份后校验完整性                                                                |

> RPO 目标 ≤ 15 分钟（见 §5）。每日一次 `mongodump` 只能恢复到当天 dump 点，**无法单独满足该 RPO**；生产必须依赖快照 + oplog 持续归档，或 MongoDB Ops Manager / 云厂商托管备份。
>
> 快照须在副本集 Secondary 上、对同一时间点的数据与 oplog 一起取（`$fsync`/locked 快照或云盘一致性快照），避免恢复后处于不一致状态。

示例：

```bash
# 开发 / 小库：逻辑备份与恢复（非生产 PITR 方案）
mongodump --uri="$MONGO_URI" --out=/backup/mongo/$(date +%F)
mongorestore --uri="$MONGO_URI" /backup/mongo/2026-10-02

# 生产：以云盘/文件系统一致性快照为全量，另持续拉取 oplog
# （快照与 oplog 归档的具体命令依所用云厂商 / Ops Manager，在此不固化）
```

### 2.2 Redis 备份

| 项目     | 说明                   |
| -------- | ---------------------- |
| RDB      | 定时快照               |
| AOF      | 追加日志，按策略 fsync |
| 备份位置 | 对象存储 / 异地机房    |
| 恢复     | 加载 RDB 或 AOF        |

示例：

```bash
# 触发 RDB 快照
redis-cli BGSAVE

# 复制备份文件
cp /data/dump.rdb /backup/redis/dump-$(date +%F).rdb
```

### 2.3 配置备份

- 所有配置纳入 Git 版本管理。
- 敏感配置加密存储，权限受控。
- 变更需记录变更人与时间。

## 3. 备份存储

| 项目     | 说明             |
| -------- | ---------------- |
| 本地备份 | 保留最近 7 天    |
| 异地备份 | 保留最近 30 天   |
| 冷备     | 归档至对象存储   |
| 加密     | AES-256 加密     |
| 访问控制 | 仅授权人员可访问 |

## 4. 恢复流程

### 4.1 恢复原则

- 恢复前确认影响范围与恢复目标。
- 优先恢复核心数据。
- 恢复过程记录时间线。
- 恢复后验证数据一致性。

### 4.2 MongoDB 恢复

1. 停止写入或切换到维护模式。
2. 选择恢复点：整库恢复取最近一致性快照；时间点恢复（PITR）取目标时间之前最近快照。
3. 从快照恢复数据文件并启动到恢复态实例；PITR 时再重放归档 oplog 到目标时间点。
4. 校验数据完整性（文档数、关键集合、oplog 重放无断点）。
5. 恢复写入，验证核心链路。

> 开发/小库的 `mongorestore` 逻辑恢复仅用于回到某个 dump 点，不提供 PITR。

### 4.3 Redis 恢复

1. 停止 Redis 服务。
2. 替换 RDB / AOF 文件。
3. 启动 Redis 并加载数据。
4. 校验关键 Key。
5. 恢复应用连接。

### 4.4 配置恢复

1. 从 Git 或配置中心拉取对应版本。
2. 校验配置内容。
3. 重启应用生效。
4. 验证服务状态。

## 5. 恢复演练

| 项目 | 要求                                        |
| ---- | ------------------------------------------- |
| 频率 | 每季度至少一次                              |
| 范围 | 覆盖 MongoDB、Redis、配置                   |
| 记录 | 演练报告与改进项                            |
| 目标 | 恢复时间 RTO ≤ 1 小时，恢复点 RPO ≤ 15 分钟 |

## 6. 备份监控

| 指标       | 说明             | 告警         |
| ---------- | ---------------- | ------------ |
| 备份成功率 | 每日备份是否成功 | 失败即告警   |
| 备份耗时   | 备份执行时长     | 异常增长告警 |
| 备份大小   | 备份文件大小     | 异常变化告警 |
| 恢复演练   | 是否按期执行     | 逾期告警     |

## 7. 安全与合规

- 备份文件必须加密。
- 备份访问需权限控制与审计。
- 备份保留周期需符合合规要求。
- 过期备份需安全销毁。
