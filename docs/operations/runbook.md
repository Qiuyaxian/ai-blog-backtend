# Runbook — 故障处理手册

本文档提供常见故障的排查步骤与应急响应流程，供值班人员快速定位与处理问题。

## 1. 应急响应总则

1. 发现告警 → 确认影响范围与严重程度。
2. 快速止损（回滚 / 限流 / 降级）。
3. 定位根因，记录时间线。
4. 修复后验证核心链路。
5. 输出复盘报告，跟进改进项。

**原则：** 先恢复，再定位，后复盘。

## 2. 故障分级

| 级别 | 说明                  | 响应时间 |
| ---- | --------------------- | -------- |
| P0   | 服务不可用 / 数据异常 | 立即     |
| P1   | 关键功能异常          | 15 分钟  |
| P2   | 非关键功能异常        | 1 小时   |
| P3   | 提示性问题            | 次日     |

## 3. 常见故障排查

### 3.1 服务不可用

排查步骤：

1. 检查容器状态：`docker-compose ps` 或平台状态页。
2. 查看应用日志：定位启动失败或崩溃原因。
3. 检查依赖服务：MongoDB、Redis 是否可用。
4. 检查资源：CPU、内存、磁盘是否耗尽。
5. 检查网络：端口、DNS、防火墙。
6. 必要时回滚到上一版本。

### 3.2 接口响应慢

排查步骤：

1. 查看 P95 / P99 延迟指标，定位慢接口。
2. 检查数据库慢查询。
3. 检查 Redis 命中率与慢命令。
4. 检查外部依赖调用耗时。
5. 检查事件循环延迟与 GC 情况。
6. 必要时限流或降级非核心功能。

### 3.3 错误率升高

排查步骤：

1. 查看错误日志，定位错误类型。
2. 检查是否与最近发布相关。
3. 检查依赖服务是否异常。
4. 检查输入参数与边界条件。
5. 必要时回滚。

### 3.4 数据库连接异常

排查步骤：

1. 检查 MongoDB 状态与副本集健康。
2. 检查连接池配置与当前连接数。
3. 检查慢查询是否长时间占用连接。
4. 检查网络与认证配置。
5. 必要时重启应用释放连接。

### 3.5 Redis 异常

排查步骤：

1. 检查 Redis 进程与持久化状态。
2. 检查内存使用与淘汰策略。
3. 检查大 Key 与慢命令。
4. 检查主从复制状态。
5. 缓存不可用时，确认应用降级逻辑生效。

### 3.6 缓存穿透 / 击穿 / 雪崩

| 问题 | 表现                    | 处理                  |
| ---- | ----------------------- | --------------------- |
| 穿透 | 大量请求查不存在的数据  | 空值缓存 + 布隆过滤器 |
| 击穿 | 热点 Key 失效瞬间压力大 | 互斥锁 + 逻辑过期     |
| 雪崩 | 大量 Key 同时失效       | 随机 TTL + 多级缓存   |

### 3.7 磁盘空间不足

排查步骤：

1. 检查磁盘使用率与增长趋势。
2. 清理日志与临时文件。
3. 检查数据库数据增长。
4. 扩容磁盘或迁移数据。
5. 配置磁盘告警。

### 3.8 内存溢出

排查步骤：

1. 检查进程内存与 GC 情况。
2. 检查是否有内存泄漏。
3. 检查缓存是否无限增长。
4. 必要时重启实例并保留现场。
5. 使用 heap dump 分析。

## 4. 应急操作

### 4.1 回滚

```bash
# 使用上一版本镜像重新启动
docker-compose up -d --no-deps --build nestjs-app
```

### 4.2 限流

- 在网关或应用层启用限流。
- 优先保护核心接口。
- 记录限流触发情况。

### 4.3 降级

- 关闭非核心功能。
- 缓存不可用时降级到数据库。
- 外部依赖不可用时返回默认值。

### 4.4 扩容

- 增加应用实例。
- 提升数据库连接池。
- 扩容 Redis 内存。

## 6. 复盘要求

- 故障后 3 个工作日内输出复盘报告。
- 报告包含时间线、根因、影响、改进项。
- 改进项需明确负责人与截止时间。
- 跟踪改进项落地情况。
