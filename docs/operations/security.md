# 安全与合规

> 适用范围：认证、授权、数据安全、审计、密钥、合规、安全监控与事件响应
> 上游文档：[架构总览](../architecture/overview.md)
> 开发规范：[架构编码规范 §6 安全编码规范](../architecture/development-standards.md#6-安全编码规范)
> 目标读者：运维 / SRE / 安全负责人 / 开发值班人员

## 1. 安全目标

- 通过 OWASP Top 10 防护要求。
- 密码使用 bcrypt 哈希存储（cost >= 10）。
- 认证、授权、输入校验、限流、审计默认开启。
- 满足《个人信息保护法》和等保基础要求。
- 关键操作可追溯，安全事件可响应。

## 2. 认证与授权

- 认证模型：JWT + Refresh Token。
- Access Token：短期有效。
- Refresh Token：长期有效，存储在 Redis，支持撤销与轮换。
- 授权模型：RBAC。
- 角色：读者、博主、管理员。
- 敏感操作需二次校验或重新认证。
- 令牌密钥、签名算法、过期时间需统一配置。
- 异常登录需触发告警。

## 3. 数据安全

- 传输加密：全站 HTTPS / TLS。
- 存储加密：敏感字段加密存储，密码只存哈希。
- 日志脱敏：禁止记录密码、令牌、密钥、完整身份证号等敏感信息。
- 数据备份：备份文件加密存储，定期恢复演练。
- 数据删除：支持用户数据导出与删除，满足合规要求。
- 数据保留：超过保留期限的数据应匿名化或删除。

## 4. 审计日志

### 4.1 记录范围

- 登录、登出、登录失败
- 权限变更、角色分配
- 文章创建、更新、删除
- 评论审核、删除
- 用户管理操作
- 敏感配置变更

### 4.2 日志字段

至少包含：

- `traceId`
- `userId`
- `action`
- `resource`
- `result`
- `ip`
- `userAgent`
- `timestamp`

### 4.3 保留与访问

- 保留周期：按等保与合规要求执行，建议不少于 180 天。
- 审计日志只追加，不允许普通管理员修改或删除。
- 访问审计日志需授权并记录访问行为。

## 5. 合规要求

- 等保：按等保要求进行安全建设与测评。
- 个人信息保护法：
  - 数据可导出。
  - 数据可删除。
  - 最小必要收集。
  - 明确告知用途。
- 数据保留策略：超过保留期限的数据应匿名化或删除。
- 合规审计：定期检查权限、日志、密钥与数据保留策略。

## 6. 密钥与配置管理

- 密钥、令牌、数据库密码不得明文落库。
- 使用环境变量或密钥管理服务注入。
- 密钥定期轮换。
- 不同环境使用不同密钥。
- 禁止将 `.env`、证书、私钥提交到版本库。
- 密钥访问需最小权限并记录审计。

## 7. 依赖与供应链安全

- 定期扫描依赖漏洞。
- 基础镜像使用可信来源，定期更新。
- 生产依赖锁定版本。
- 新依赖引入前评估安全性与维护状态。
- 禁止引入无维护、无许可证或来源不明的依赖。

## 8. 安全监控与告警

| 告警项   | 条件示例                     | 级别  | 通知渠道  |
| -------- | ---------------------------- | ----- | --------- |
| 异常登录 | 频繁失败、异地登录、暴力破解 | P1/P2 | 电话 / 群 |
| 权限异常 | 越权访问、角色提升           | P1    | 电话 / 群 |
| 流量异常 | 突增请求、限流触发           | P2    | 群        |
| 数据异常 | 批量导出、批量删除           | P1    | 电话 / 群 |
| 依赖漏洞 | 高危漏洞出现                 | P2    | 群        |

- 告警接入监控/日志服务。
- 明确通知渠道与责任人。
- 关键告警必须关联 Runbook。

## 9. 安全事件响应

- 事件分级：一般、严重、紧急。
- 响应流程：发现、上报、止损、取证、修复、复盘。
- 联系人：安全负责人、运维负责人、架构组。
- 回滚与降级优先于定位根因，先恢复业务。
- 事件记录归档，用于复盘与合规审计。
