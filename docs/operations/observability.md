# 可观测性

> 适用范围：日志、指标、追踪、告警、SLO/SLI 的采集、存储、展示与运维
> 上游文档：[架构总览](../architecture/overview.md)
> 开发接入规范：[架构编码规范 §4 可观测性编码规范](../architecture/development-standards.md#4-可观测性编码规范)
> 目标读者：运维 / SRE / 开发值班人员
>
> 本文件是监控、指标、告警、SLO 的唯一权威文档；应用日志字段定义见 [logging.md](./logging.md)。

## 1. 目标与原则

- 关键链路具备日志、指标、追踪和告警。
- 上线前完成可观测性接入，避免“先上线后补监控”。
- 日志、指标、追踪统一携带 `traceId`，便于关联排查。
- 告警基于 SLO / 错误预算，避免无效告警。
- 可观测性数据按合规要求脱敏、留存和访问控制。

## 2. 监控体系与工具

| 层级        | 监控对象              | 关键指标               |
| ----------- | --------------------- | ---------------------- |
| 基础设施    | CPU、内存、磁盘、网络 | 使用率、IO 等待        |
| 容器 / 进程 | 容器状态、重启次数    | 存活、重启频率         |
| 应用        | 请求、错误、延迟      | QPS、错误率、P95 / P99 |
| 依赖        | MongoDB、Redis        | 连接数、慢查询、命中率 |
| 业务        | 核心业务链路          | 成功率、关键业务指标   |

| 工具                 | 用途             |
| -------------------- | ---------------- |
| Prometheus           | 指标采集与存储   |
| Grafana              | 指标可视化与看板 |
| Alertmanager         | 告警路由与收敛   |
| OpenTelemetry        | 链路追踪         |
| Elasticsearch / Loki | 日志存储与查询   |

应用通过 `/metrics` 暴露 Prometheus 指标，通过 `GET /health` 暴露健康检查。

## 3. 日志

- 格式：Pino 结构化 JSON；级别、必填字段、字段定义、保留与脱敏要求以 [logging.md](./logging.md) 为准。
- 关键链路日志必须携带 `traceId`；禁止记录密码、令牌、密钥等敏感信息。
- 采集：stdout 输出，由容器日志驱动 / Filebeat / Fluent Bit 采集到 Elasticsearch / Loki。

## 4. 指标

### 4.1 应用指标

| 指标         | 说明                | 阈值建议               |
| ------------ | ------------------- | ---------------------- |
| 请求量 QPS   | 每秒请求数          | 按容量设定             |
| 错误率       | 5xx / 总请求        | > 1% 关注，> 5% 告警   |
| 响应延迟 P95 | 95 分位响应时间     | > 500ms 关注           |
| 响应延迟 P99 | 99 分位响应时间     | > 1s 关注，> 2s 告警   |
| 缓存命中率   | Redis 命中 / 总查询 | < 80% 关注，< 60% 告警 |
| 数据库连接数 | 活跃连接数          | > 90% 告警             |
| 事件循环延迟 | Node.js Event Loop  | > 100ms 关注           |
| 进程内存     | RSS 使用量          | 接近上限告警           |

业务指标另含：登录成功/失败数、文章阅读数、评论数。

### 4.2 MongoDB

| 指标       | 说明       | 阈值建议         |
| ---------- | ---------- | ---------------- |
| 连接数     | 当前连接数 | > 90% 上限告警   |
| 慢查询     | 慢查询数量 | > 10 / 分钟 关注 |
| 复制延迟   | 副本集延迟 | > 10s 告警       |
| 磁盘使用率 | 数据盘使用 | > 85% 告警       |
| 副本集状态 | 主从状态   | 非健康即告警     |

### 4.3 Redis

| 指标       | 说明                   | 阈值建议         |
| ---------- | ---------------------- | ---------------- |
| 连接数     | 客户端连接数           | > 90% 上限告警   |
| 内存使用   | used_memory            | > 85% 告警       |
| 命中率     | hits / (hits + misses) | < 60% 告警       |
| 慢命令     | slowlog 数量           | > 10 / 分钟 关注 |
| 主从延迟   | 复制偏移               | > 1s 告警        |
| 持久化状态 | RDB / AOF 状态         | 失败即告警       |

## 5. 追踪

- 标准：OpenTelemetry；传播：HTTP Header 传递 `traceparent`。
- 关键 Span：HTTP 请求、数据库查询、Redis 操作、外部依赖调用。

| 场景        | 策略                    |
| ----------- | ----------------------- |
| 开发 / 测试 | 全量采样                |
| 正常请求    | 按比例采样，如 1% ~ 10% |
| 错误请求    | 全量采集                |
| 慢请求      | 超过阈值全量采集        |
| 关键链路    | 提高采样率或全量        |

## 6. 告警

### 6.1 告警分级

| 级别 | 说明                  | 响应方式      | 响应时间 |
| ---- | --------------------- | ------------- | -------- |
| P0   | 服务不可用 / 数据异常 | 电话 + 群通知 | 立即     |
| P1   | 关键指标异常          | 群通知 + 值班 | 15 分钟  |
| P2   | 非关键指标异常        | 群通知        | 1 小时   |
| P3   | 提示性告警            | 记录待处理    | 次日     |

### 6.2 告警规则

| 告警项         | 条件                        | 级别 |
| -------------- | --------------------------- | ---- |
| 服务不可用     | 健康检查连续失败 3 次       | P0   |
| 错误率突增     | 5xx 错误率 > 5% 持续 5 分钟 | P0   |
| 错误率升高     | 5xx 错误率 > 1% 持续 5 分钟 | P1   |
| 数据库不可用   | MongoDB 连接失败            | P1   |
| Redis 不可用   | Redis 连接失败              | P1   |
| 延迟升高       | P99 > 2s 持续 5 分钟        | P1   |
| 缓存命中率下降 | 命中率 < 60% 持续 10 分钟   | P1   |
| 数据库连接耗尽 | 连接数 > 90%                | P1   |
| Redis 内存告警 | 内存使用 > 85%              | P2   |
| 磁盘空间不足   | 使用率 > 85%                | P2   |
| 证书即将过期   | 剩余有效期 < 30 天          | P3   |

安全类告警（异常登录、越权、批量导出等）见 [security.md §8](./security.md#8-安全监控与告警)。

### 6.3 告警收敛与响应

- 同类告警 5 分钟内合并，避免告警风暴；维护窗口内静默非关键告警。
- 告警必须可追溯到具体实例与时间点，重复告警需升级或降级。
- 每个 P1/P2 告警必须关联 Runbook，附带排查入口。
- 响应流程：收到告警 → 确认级别与影响范围 → P0/P1 立即响应并通知 → 按 [runbook.md](./runbook.md) 处理 → 记录时间线与根因 → 复盘。

## 7. SLO / SLI

### 7.1 SLI

- 可用性：成功请求数 / 总请求数。
- 延迟：核心接口 P95 / P99。
- 错误率：5xx 请求占比。
- 缓存命中率：Redis 命中次数 / 总访问次数。

### 7.2 SLO

| 指标         | 目标    |
| ------------ | ------- |
| 可用性       | 99.9%   |
| 文章详情 P99 | < 200ms |
| 文章列表 P99 | < 300ms |
| 登录 P99     | < 500ms |

### 7.3 错误预算

- 按月度计算。
- 错误预算消耗过快时触发告警并暂停非必要发布。
- 错误预算燃尽率告警：如 1 小时燃尽 5%、6 小时燃尽 10%。
